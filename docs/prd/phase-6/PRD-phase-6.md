## P0 · 采集周期 7→14 / 14→21

**要做：** 采得没那么勤。5 个原 7 天品类改 14 天；其余 19 个改 21 天。旧数据全留着。

下次采集 = 该品类**已发布最新周期起点 + 新天数**（按品类各自最新档，不是全局日历格子）。例：最新均为 **2026-08-24** 时，原 7→14 下次 **2026-09-07**，原 14→21 下次 **2026-09-14**；若某 21 天品类最新仍是 **08-10**，则 **08-31** due。Cron 仍每周一跑，未 due 品类 skip；同一周一未发布前重跑仍 due。

旧快照保留。Δ / 趋势用发布序列相邻点。未知品类默认仍 7 天，只改现有 24 个配置。

| 原 | 新 | 品类 |
|----|----|------|
| 7 | 14 | AI Tools、AI Image / Video Tools、Marketing Tools、AI Meeting Assistants、AI Cybersecurity Tools |
| 14 | 21 | 其余 19 个 |

## P1 · Brand 官网入口

**要做：** 产品详情页（`/brand/[slug]`）能点进该产品官网。

**现在：** Brand 表没有官网字段。只有线索 `leads.website`。Brand 页没有外链官网。

**做成：**

1. Brand 增加 `website`（可空 URL）。有值才在详情页标题旁显示「官网」入口，新标签打开。
2. 没有 URL 不显示入口，不留空按钮。
3. 本阶段给近期上榜热门品牌补一批官网（手填 / seed 表均可）：至少覆盖各品类最新 Overall Top20 里已有 Brand 页的产品。缺的以后再补。

- [x] P1-1：**新增** Brand.`website` + Brand 页官网链接（有值才显）。
- [x] P1-2：**新增** 热门上榜品牌官网补数（各品类最新 Overall Top20）。
- [x] P1-3：**验收** 有 website 的 Brand 页可点进官网；无 website 的页没有该入口。

## P2 · Watch

**要做：** 用户盯「一个产品 × 一个锚定品类」的名次变化；邮箱验证后，按该品类采集周期发邮件。

**现在：** Brand 页大按钮是销售表（邮箱 + 网站 + 留言 +「监控/诊断」混入口）。提交进 `leads`，无验证信、无周期邮件。Category 页无 Watch 入口。

**入口**

| 页面 | 可订阅对象 | CTA |
|------|------------|-----|
| `/brand/[slug]` | 当前品牌 × 锚定品类（从品类点进来则用该品类；否则用名次最好的品类） | 主按钮「监控该品牌的 AI 可见度」类文案 |
| `/category/[slug]` | 榜内某一产品（Top 20 / Also mentioned 行） | 行内「监控该产品」 |
| `/category/[slug]` | 本品类整榜摘要（可选，本阶段若工期紧可后置） | 「监控本品类」 |

**用户应立刻知道**

- 盯的是谁：品牌名 / 品类名只读带入，不手填
- 会收到什么：排名、Δ、是否跌出 Top 20
- 多久一次：跟随该品类采集周期（14 / 21 天）；**每对象每周期最多一封**；无变化不发
- 怎么停：邮件内退订

**最小表单**

- 邮箱（必填）
- 监控对象（只读：品牌 + 品类，或整榜时仅品类）
- 提交 = 发验证邮件 → 点开才生效；未验证不发名次信
- 同一品牌+品类再提交不重复订

**做成（锁死）**

1. Brand 页主 CTA = Watch（只填邮箱）。拆掉现有 `track_brand` / `geo_audit` 混表。
2. Category 行可 Watch 该行产品（品类=本页）。
3. 验证成功后，Watch 成功态下可**轻量二次**「需要人看一遍？」（仍进 `geo_audit`）；未验证不出现。主按钮仍是 Watch。
4. 该品类下次采集并发布后：名次变了 / 跌出 Top20 → 最多一封，写清新旧名次；没变不发。
5. 邮件内退订；退订后不再发。

- [ ] P2-1：**新增** Watch 订阅（品牌×品类；可选整榜）+ 验证邮件；未验证不发名次信。
- [ ] P2-2：**新增** 每对象每周期最多一封；无变化不发；间隔跟品类采集天数。
- [ ] P2-3：**变更** Brand 主按钮 = Watch；Category 行可 Watch；拆掉 leads 混表。
- [ ] P2-4：**变更** 诊断只出现在验证成功后轻量二次。
- [ ] P2-5：**验收** 真邮箱：验证 → 收到或正确跳过 → 退订失效。
- [ ] P2-6：**验收** 两个采集周期后记验证数、发送数。

## P3 · 建议新品类

**要做：** 用户建议平台覆盖尚不存在（或未发布）的品类，入库供选品参考。

**入口**

- `/rankings`：搜索无结果、或页脚 / 分组旁常驻「建议新品类」
- 可选（后置）：未发布品类卡片「上线时通知我」（复用 Watch 邮件基建，意向不同）

**最小表单**

- 建议品类名（必填）
- 一句话场景 / 为什么需要（可选）
- 邮箱（可选：上线或进入调研时通知）
- 可选：已知竞品 / 代表品牌 2–3 个（帮助评估可采集性）

**用户应立刻知道**

- 这是「建议新品类」，上线时间未定
- 按 [category-selection](../category-selection.md) 标准评估
- 留了邮箱才可能收到通过 / 不通过 / 已进候选的通知

**与选品**

- 请求入库 → 人工 / 半自动对照入选标准 → 进 category-selection 候选池

- [ ] P3-1：**新增** `/rankings` 建议新品类表单（品类名必填；场景 / 邮箱 / 竞品可选）。
- [ ] P3-2：**验收** 文案写清「建议已收到、上线未定」；提交入库。

## P4 · 周期发布提醒

**要做：** 用户订阅「本品类下一周期发布时通知我」。只通知「新一期已上线」+ 链接，比 Watch 整榜变化摘要更轻。复用 P2 验证邮件 / 退订。

**入口**

- `/category/[slug]`：本品类
- `/rankings`：品类卡片或分组旁

**最小表单**

- 邮箱（必填）
- 品类（只读，来自当前页 / 卡片）
- 提交 = 发验证邮件 → 点开才生效

**用户应立刻知道**

- 盯的是哪个品类
- 下一期该品类发布后会收到一封（跟采集周期走）
- 邮件里有退订

**做成（锁死）**

1. 该品类新周期 Overall 发布成功后发一封，带周期起始日和品类页链接。
2. 同一邮箱 + 同一品类不重复订。
3. 验证前不发。

- [ ] P4-1：**新增** 周期发布提醒订阅（品类 × 邮箱；验证后生效）。
- [ ] P4-2：**验收** 发布后收到提醒；退订失效。
